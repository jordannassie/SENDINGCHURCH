# Sending Church

Next.js app with Supabase, deployed on Netlify.

## Local setup

```bash
npm install
cp .env.local.example .env.local
npm run dev
```

Fill `.env.local` from the Supabase project dashboard (Project Settings → API).

## Frisco lead tracker

`/dashboard/leads` is a private Meta CSV importer. The public site login stays a demo. The lead tracker uses Supabase Auth with Google.

1. In Supabase → Authentication → Providers, enable Google.
2. In Authentication → URL configuration, allow:
   - `https://sending.church/auth/callback`
   - `http://localhost:3000/auth/callback` for local sign-in
3. Keep `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` (or `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`) in the environment. Do not put the service-role key in the browser.
4. The supplied SQL creates `public.sending_lead_admins` and `public.sending_leads`. Add an admin from the SQL editor only, for example `insert into public.sending_lead_admins (user_id) values ('the-auth-user-uuid');`. The app does not let anyone add themselves.
5. Row Level Security on those tables is what protects the data. A signed-out visitor is sent to `/login?next=/dashboard/leads`. A signed-in person who is not in `sending_lead_admins` sees an access-denied page.

Imports insert new rows only (`onConflict: phone_normalized`, `ignoreDuplicates: true`). `phone_normalized` is generated by the database and is never written by the app.
